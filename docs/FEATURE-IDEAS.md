# dsh-op-splash 功能建议书

> 策划顾问视角的扩展建议，供后续开发选型参考。
> 基线版本：v1.3.0（2026-10-26）

## 前提说明

这个插件是 **DSH（DeepSeek Harness）插件**，不是 Obsidian 插件。文件构成：

- `lib/index.js` — Host 半（路由注册 + index.html 注入 + 配置读写 + 素材扫描）
- `lib/client.js` — 浏览器半（设置页「开场动画」面板）
- `lib/splash.js` — 播放器（冷启动时全屏播放）
- `lib/splash.css` — 播放器样式

因此「Obsidian 社区插件库」里没有同类可直接对照；本建议书的参考来自 Steam Deck 启动动画插件、移动端 splash 实践、以及通用启动体验设计。

## 一、基线：当前已有能力

| 方面 | 已有能力 |
| --- | --- |
| 播放 | 冷启动全屏播放；视频（原声、逐帧）与图片（淡入—停留—淡出）两种形式；failsafe 兜底（10 秒或时长+3s）绝不锁死黑屏 |
| 选择 | 总开关；动画选择器（内置 + 自导入）；播放频率（每次启动 / 每会话一次 / 每天一次） |
| 随机 | 每次启动随机挑一个；随机池（只随机勾选的几件）；每件权重（0 = 不参与） |
| 时段 | 按时段指定素材；支持跨零点；列表顺序即优先级 |
| 图片 | 停留 2 / 3 / 5 秒、一直停到手动跳过、自定义 1–600 秒 |
| 提示 | 跳过提示位置（底部居中 / 左下 / 右下 / 不显示）与文案（1–40 字）；点画面、Esc、Enter、空格跳过 |
| 素材 | 导入视频/图片（≤300MB，流式写盘）；素材清单（类型/时长/体积/来源）；缺失自检（素材丢了 / 没 manifest / manifest 坏了） |
| 其他 | 音量；立即预览；配置存 `~/.dsh/dsh-op-splash.json`；五套测试 178 项断言 |
| 隔离 | 独立 DOM id / 存储键 / 路由前缀 / CSS 类，不碰 dsh-startup-screen 任何文件 |

（待补充：macOS / Linux 桌面端是否实测过 —— 目前只在 Windows 机器上验证。）

## 二、参考来源

- [SDH-AnimationChanger](https://github.com/TheLogicMaster/SDH-AnimationChanger) — Steam Deck 的 Decky 插件：开机/休眠动画分开管理、随机化、快捷菜单直接切换、动画包下载。**可借鉴**：按「事件/场景」分组组织素材。
- [Obsidian 论坛：Background startup – No Splash screen](https://forum.obsidian.md/t/background-startup-no-splash-screen-feature-request/74140) — 用户明确要后台启动、不要启动画面；社区解法是后台预热 + 自动最小化。**印证**：静默启动是真实需求。
- [Lottie 免费 splash 动画库](https://lottiefiles.com/free-animations/splash-screen) — 矢量动画素材，体积小、任意分辨率。
- [React Native 关于 Lottie splash 的讨论](https://www.reddit.com/r/reactnative/comments/xndg6h/lottie_animation_as_splash_screen/) — 反方观点：过长的启动动画本身伤害体验。**可借鉴**：给动画设时长上限。
- [视频播放器 UX 最佳实践](https://www.vidzflow.com/blog/mastering-video-player-controls-ux-best-practices) — 进度条与可见跳过入口是标配（本插件已实现）。
- [What's New 更新屏通行做法](https://features.vote/swiftui-whats-new-screen) — 版本变化后先给一屏「这次更新了什么」。

## 三、建议总表

优先级：高 = 直接影响日常使用或挡住真实故障；中 = 明显提升完善度；低 = 锦上添花。

### A. 播放与时机

| # | 功能 | 解决什么 | 实现思路 | 优先级 |
| --- | --- | --- | --- | --- |
| A1 | 静默启动 | 着急干活时不想等动画 | 加一个「不播动画直接进主界面」的开关；再给 `?nosplash=1` 与环境变量 `DSH_OP_SPLASH_DISABLE=1` 两条临时绕过通道 | 高 |
| A2 | 真实就绪联动 | 固定时长要么让人等、要么播不完 | 宿主已就绪就提前收尾，未就绪则延长；改成「最少停留 + 就绪即走」 | 高 |
| A3 | 时长上限 | 长素材拖慢启动 | 单条素材可设「最长播 N 秒」，到点自动收尾（保留手动跳过） | 中 |
| A4 | 播完落到哪 | 每次都要自己找回原来的会话 | 可配「主界面 / 上次会话 / 指定工作区」 | 中 |
| A5 | 启动里程碑文本 | 冷启动黑屏期间不知道在等什么 | 动画角落显示真实加载进度（宿主已有「模块 3/8」这类信息） | 中 |

### B. 素材与内容

| # | 功能 | 解决什么 | 实现思路 | 优先级 |
| --- | --- | --- | --- | --- |
| B1 | Lottie/JSON 矢量素材 | 视频体积大、放大糊 | 新增 `kind: 'lottie'`，播放器引入轻量 svg 渲染；manifest 声明 file 为 .json | 中 |
| B2 | 首帧封面 | 开场闪黑、清单里看不出是什么 | 导入时用 canvas 抽第一帧存 `poster.png`；清单与选择器显示缩略图 | 中 |
| B3 | 素材元数据编辑 | 改个标题还得手改 manifest | 面板里直接改 title / duration / 换封面 | 中 |
| B4 | 多图幻灯片 | 想让几张图轮着看 | 一个条目声明 `files: []`，播放器按序淡入淡出（注意：老大上次划掉的是「视频图片串播」，本条仅作为一图多条时的替代品留档） | 低 |
| B5 | 内置无版权示例素材 | 装上没东西可播 | 随包附 1–2 段自制/CC0 动画，开源时也当默认素材 | 中 |
| B6 | 批量导入 / 拖文件夹 | 一次只能导一个 | 支持多选与目录拖放，逐个走现有导入链路 | 低 |
| B7 | 体积提示与压缩建议 | 大素材拖慢启动 | 清单里标出「较大」并给压缩建议（插件不带 ffmpeg，只提示不转码） | 中 |

### F. 性能与兼容

| # | 功能 | 解决什么 | 实现思路 | 优先级 |
| --- | --- | --- | --- | --- |
| F1 | 素材预加载与缓存 | 每次冷启动都从磁盘读整段视频 | 用 Cache Storage 缓存已取过的素材，二次启动直接命中 | 中 |
| F2 | 窄屏/竖屏适配 | 竖屏素材留白难看 | 可配 letterbox / 裁切填充 / 模糊背景三种策略 | 中 |

### H. 可靠性与诊断

| # | 功能 | 解决什么 | 实现思路 | 优先级 |
| --- | --- | --- | --- | --- |
| H1 | 播放看门狗 | 播放器卡住时页面不恢复 | 播放期心跳，超时未推进就自愈收尾（现有 failsafe 只兜住「根本没起来」） | 中 |
| H2 | 诊断面板 | 出问题只能翻文件排查 | 只读展示：路由是否注册、素材是否可读、上次播放结果与耗时 | 中高 |
| H3 | 播放日志 | 不知道上次到底播没播 | 记最近 10 次：时刻、素材、来源、是否被跳过、失败原因 | 中 |
| H4 | 一键自检 | 素材坏了不知道 | 遍历素材做可读性检查 + 路由探测，给一份结果 | 中 |

## 四、先做哪三条

1. **H2 诊断面板** —— 出问题时不用再翻文件、翻日志、翻路由（这次排查跳过提示时最费时间的正是这些）。
2. **G1 按星期几** —— 补完时段场景最后一块拼图，实现量小、旧配置无感。
3. **J1 互斥检测** —— 挡掉「两个启动画面打架」这类最容易被当成 bug 的体验问题。
